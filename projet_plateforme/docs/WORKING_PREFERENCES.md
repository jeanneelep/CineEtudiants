# Working Preferences - CinéÉtudiants

## 📌 Key Principles

### 1. Explain Before Coding
**When proposing a solution, explain it first and ask for confirmation before implementing.**

- Discuss the "why" behind technical decisions
- Get approval before architecture changes
- Keep the user in control

### 2. Stop Coding When Asked
**If user says "arrête de coder" or asks for explanation, stop immediately and switch to discussion mode.**

- Respect the user's need to understand the full picture
- Pivot to explanation/planning instead of continuing code work
- No silent code changes

### 3. Build Memory/Documentation First
**Before coding, create comprehensive documentation about:**
- Project requirements
- Tech stack choices
- Architecture decisions
- User preferences

**Why**: Avoids repeated explanations and ensures consistency across sessions.

### 4. Student Project = MVP Focus
**Don't over-engineer or add unnecessary complexity.**

- Simple solutions first
- Save optimization for later phases
- Don't add features not explicitly requested
- Keep code maintainable but not production-perfect

### 5. French Language Welcome
**User sometimes communicates in French.**

- Respond in French when user initiates in French
- Keep technical terms in English
